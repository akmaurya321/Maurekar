Binary Search / Basics · Topic 02

Lower Bound.

Big Picture (read this first, 30 seconds): Lower Bound answers one question: “In a sorted list, what is the first position where a value that is greater than or equal to my target could go?” It is basically Binary Search, but instead of just finding an exact match, it finds the first valid boundary point. This one idea powers “insert position,” “first occurrence,” and hundreds of LeetCode/GFG problems. Keep this one line in your head — everything below just explains it in full detail, step by step.

RequirementSorted data
TimeO(log N)
BoundaryFirst arr[i] ≥ target

1. WHY (Motive) — Why Do We Need Lower Bound?

Imagine a sorted list of 1 million exam scores, from lowest to highest. You want to answer:

“What is the first score that is at least 60 (the passing mark)?”

Without Lower Bound (checking one by one)

  • You would start from the first score and keep checking, one at a time, until you find a score ≥ 60.
  • In the worst case, that is up to 1 million checks.

With Lower Bound

  • Just like normal Binary Search, check the middle and ask: “Is this value ≥ 60?”
  • Based on yes/no, cut the list in half again and again.
  • Find the answer in about 20 steps instead of a million.

Simple takeaway: Lower Bound is Binary Search’s cousin. Instead of asking “does this exact value exist?”, it asks “where is the first place this condition becomes true?” Same speed — O(log N) — but it answers a more flexible, more useful question.

2. CONDITION (Prerequisite) — The List Must Be Sorted

Exactly like Binary Search, Lower Bound only works on a sorted list in ascending order.

Why? Once you find one value that is ≥ target, you know for certain that everything after it is also ≥ target, because the list is sorted. This lets you safely ignore half the list at every step.

If the list is not sorted, this guarantee breaks, and Lower Bound gives wrong answers.

Rule to remember: Sorted list → Lower Bound works perfectly. Unsorted list → sort it first, or do not use this technique.

3. INTUITION (The Core Logic) — The Exam Pass/Fail Story

A teacher has a list of 10 students’ exam scores, already sorted from lowest to highest:

40, 45, 52, 58, 60, 65, 70, 78, 85, 90

The passing mark is 60. The teacher wants to know: “Where does the passing zone begin?” — what is the first score that is 60 or above?

Everything before that point failed. Everything from that point onward passed.

  • Check the middle score. Ask: “Is this score ≥ 60?”
  • If yes, this could be our answer, but maybe there is an earlier one too. Keep this position in mind and search the left half.
  • If no, this score failed, so the passing zone must start somewhere to the right.
  • Repeat on the smaller half until you find the exact boundary — the very first “passed” score.

This is Lower Bound in one sentence: “Find the first position in a sorted list where the value stops being ‘too small’ and becomes ‘big enough.’” It is the same “cut in half” trick as Binary Search, but instead of stopping at an exact match, it hunts for a boundary line between “not enough” and “enough.”

4. DRY RUN (Simulation) — Watching the Pointers Move

Let us dry run Lower Bound on a list with duplicate values. This is where Lower Bound really shows its power — plain Binary Search struggles here, but Lower Bound handles it cleanly. 

Index:  0    1    2    3    4    5    6
Value: [10, 20,  20,  20,  30,  40,  50]

We want the Lower Bound of 20 — the index of the first occurrence of 20.

low (L) is the start of the search area, high (H) is one past the end, and mid (M) is the middle point we check.

Step 1 → L=0, H=7, M=3

arr[M] = 20, which is ≥ 20. This could be our answer, but there might be an earlier 20. Keep searching left → H becomes M = 3.

Step 2 → L=0, H=3, M=1

arr[M] = 20, still ≥ 20. Again, there could be an earlier one. Keep searching left → H becomes M = 1.

Step 3 → L=0, H=1, M=0

arr[M] = 10, which is less than 20. This is not our answer, and nothing to the left matters. Search right → L becomes M + 1 = 1.

Step 4 → L=1, H=1

L and H are equal — the loop stops here.

Answer: index 1 — the first 20 in the list. Check the array: index 1 is indeed the first 20.

Every time we find a value ≥ target, we do not stop immediately — we remember it and keep checking the left side. Every time we find a value < target, the answer must be to the right. We stop when low and high meet — that meeting point is the answer.

5. CODE (Implementation + Comments)

Python

def lower_bound(arr, target):
    low = 0                      # start of the search area
    high = len(arr)              # NOTE: one past the last index (not len - 1)

    while low < high:            # keep going while there is a real range to search
        mid = low + (high - low) // 2   # safe middle point

        if arr[mid] < target:    # this value is too small, answer is to the right
            low = mid + 1
        else:                    # big enough, but maybe not the FIRST one
            high = mid            # keep this as a possible answer, search left

    return low                   # low == high here — lower bound index

# Python also has a built-in version:
# from bisect import bisect_left
# bisect_left(arr, target)

C++

int lowerBound(vector<int>& arr, int target) {
    int low = 0;                          // start of the search area
    int high = arr.size();                // NOTE: one past the last index

    while (low < high) {                  // keep going while there is a real range
        int mid = low + (high - low) / 2; // safe middle point

        if (arr[mid] < target) {          // too small, answer is to the right
            low = mid + 1;
        } else {                          // big enough, but maybe not the FIRST one
            high = mid;                   // keep as possible answer, search left
        }
    }
    return low;                           // this is the lower bound index
}

// int idx = lower_bound(arr.begin(), arr.end(), target) - arr.begin();

Java

public class LowerBound {
    public static int lowerBound(int[] arr, int target) {
        int low = 0;                          // start of the search area
        int high = arr.length;                // NOTE: one past the last index

        while (low < high) {                  // keep going while there is a real range
            int mid = low + (high - low) / 2; // safe middle point

            if (arr[mid] < target) {           // too small, answer is to the right
                low = mid + 1;
            } else {                           // big enough, but maybe not the FIRST one
                high = mid;                    // keep as possible answer, search left
            }
        }
        return low;                            // this is the lower bound index
    }

    public static void main(String[] args) {
        int[] arr = {10, 20, 20, 20, 30, 40, 50};
        int target = 20;
        System.out.println("Lower Bound index: " + lowerBound(arr, target));
    }
}

6. MISTAKES & EDGE CASES (The Bugs)

  1. Using high = arr.length - 1 instead of high = arr.length: In normal Binary Search, the answer is always an existing index. In Lower Bound, the answer could be “insert at the very end,” so high must start at length, one past the last valid index.
  2. Using high = mid - 1 instead of high = mid: When arr[mid] >= target, this position is a possible answer. Keep it in the search area and move high to mid.
  3. Using low <= high instead of low < high: Lower Bound narrows down to one meeting point, rather than checking a specific index for equality.
  4. Forgetting that “not found” means “insert position”: If the target is bigger than everything, Lower Bound returns arr.length. This is a feature, not a bug.
  5. Confusing Lower Bound with Upper Bound: Lower Bound is the first index where arr[i] >= target. Upper Bound is the first index where arr[i] > target. Mixing them up gives wrong answers with duplicates.

7. COMPLEXITY (The Math)

Time Complexity: O(log N)

Like Binary Search, every step cuts the search area in half. For a list of 1 million items, Lower Bound needs only about 20 steps.

Space Complexity: O(1)

The loop-based version uses only three variables — low, high, and mid — no matter how big the list is.

8. REAL WORLD (Applications)

  • Search Insert Position: Finding where a new value should be inserted to keep a sorted list sorted, as in Python’s bisect.insort and database index insertion.
  • Counting elements in a range: To count numbers between X and Y, compute lower_bound(Y+1) - lower_bound(X).
  • First Bad Version: Finding the first commit or version where a bug appears is “find the first position where the condition becomes true.”
  • Auto-suggestions / Range Queries: Databases and search engines find the start of matching results, such as all products priced ≥ ₹500.
  • Leaderboards / Rankings: Finding the first player with a score ≥ a cutoff in a sorted leaderboard.

9. PATTERN RECOGNITION (Advanced) — The Boundary-Finding Pattern

Whenever a problem asks for the first position where a condition changes from false to true in a sorted or monotonic sequence, it is a Lower Bound style problem — even if the words “lower bound” never appear.

Examples of the same pattern

  • “Find the first bad version” → first position where isBad() == true
  • “Find the smallest capacity that works” → first value where canFinish() == true
  • “Find the insert position” → first position where arr[i] >= target
  • “Count how many elements are smaller than X” → Lower Bound gives this directly
Key takeaway: Lower Bound is a template for any “find the first true” question on sorted or monotonic data. Once you recognize it, dozens of hard problems start looking like the same simple idea.
