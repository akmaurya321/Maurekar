Binary Search / Basics · Topic 03

Upper Bound.

Big Picture (read this first, 30 seconds): Upper Bound answers one question: "In a sorted list, what is the first position where a value becomes strictly greater than my target?" It is almost identical to Lower Bound: Lower Bound looks for >= target, while Upper Bound looks for > target. That tiny difference changes the boundary when duplicates exist.

RequirementSorted data
TimeO(log N)
BoundaryFirst arr[i] > target

1. WHY (Motive) — Why Do We Need Upper Bound?

Imagine an online store with 1 million products, sorted by price. Your budget is Rs 2000 and you want the first product that costs strictly more than Rs 2000.

"What is the first product I truly cannot afford?"

Without Upper Bound (checking one by one)

  • Scan prices one at a time until one crosses the budget.
  • In the worst case, that means up to 1 million checks.

With Upper Bound

  • Check the middle and ask: "Is this strictly greater than 2000?"
  • Cut the list in half repeatedly and find the answer in about 20 steps.

Simple takeaway: Upper Bound is Lower Bound's twin. Both find a boundary in O(log N); Lower Bound uses >=, while Upper Bound uses > and skips every value equal to the target.

2. CONDITION (Prerequisite) — The List Must Be Sorted

Upper Bound only works on a sorted list in ascending order.

Why? Once one value is strictly greater than the target, every value after it is also strictly greater. This guarantee lets binary search remove half the list at every step.

Rule to remember: No sorted list means no Upper Bound. Sort first if needed. The sorted order is what makes the boundary monotonic.

3. INTUITION (The Core Logic) — The Online Shopping Budget Story

Consider sorted prices: 500, 800, 1200, 2000, 2000, 2000, 3500, 5000. With a budget of 2000, all three products priced exactly 2000 are affordable. The first unaffordable price is 3500.

If the middle value is strictly greater than the target, it may be the answer, but an earlier answer could exist on the left. If it is less than or equal to the target, it is still affordable, so the boundary must be on the right.

  • Ask: "Is the middle price strictly greater than 2000?"
  • If yes, it may be the answer. Save it and search left for an earlier one.
  • If no (the value is less than or equal to 2000), the boundary must be to the right.
  • Repeat until the first strictly greater position remains.

This is Upper Bound in one sentence: Find the first position where a sorted value stops being affordable or equal and becomes strictly more than the limit. Lower Bound stops at the first 2000; Upper Bound skips all 2000 values.

4. DRY RUN (Simulation) — Watching the Pointers Move

We want the Upper Bound of 20 in this duplicate-heavy sorted list: the first value strictly greater than 20. 

Index:  0    1    2    3    4    5    6
Value: [10, 20,  20,  20,  30,  40,  50]

low starts at 0, high is one past the end (7), and mid is the checked position.

Step 1 → L=0, H=7, M=3

[10, 20, 20, 20, 30, 40, 50]
 L               M          H

arr[3] = 20. It is not strictly greater, so search right: low = 4.

Step 2 → L=4, H=7, M=5

[30, 40, 50]  (checking original indexes 4–6)
 L       M   H

arr[5] = 40. This is strictly greater and could be the answer, so search left: high = 5.

Step 3 → L=4, H=5, M=4

[30, 40]  (checking original index 4)
 L/M      H

arr[4] = 30. This is also strictly greater, so keep looking left: high = 4.

Step 4 → L=4, H=4

The loop stops. Answer: index 4, where the first value strictly greater than 20 is 30.

Lower Bound on the same array returns index 1. Therefore upper_bound - lower_bound = 4 - 1 = 3, the count of values equal to 20. The gap between the two boundaries is the frequency of the target.

5. CODE (Implementation + Comments)

Python

def upper_bound(arr, target):
        low = 0                      # start of the search area
    high = len(arr)              # one past the last index

        while low < high:            # keep searching while a range remains
          mid = low + (high - low) // 2   # safe middle point

          if arr[mid] <= target:   # equal or smaller, still affordable: go right
            low = mid + 1
          else:                    # strictly greater: possible answer
            high = mid           # search left for an earlier one

        return low                   # low == high: upper bound index

C++

int upperBound(vector<int>& arr, int target) {
    int low = 0;
    int high = arr.size();

    while (low < high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] <= target) low = mid + 1;
        else high = mid;
    }
    return low;
}

public static int upperBound(int[] arr, int target) {
        int low = 0;                          // start of the search area
        int high = arr.length;                // one past the last index

        while (low < high) {                  // keep searching while a range remains
          int mid = low + (high - low) / 2; // safe middle point
          if (arr[mid] <= target) {         // equal or smaller: go right
            low = mid + 1;
          } else {                           // strictly greater: possible answer
            high = mid;                    // search left for an earlier one
          }
    }
        return low;                           // low == high: upper bound index
      }

6. MISTAKES & EDGE CASES (The Bugs)

  1. Using < instead of <=: that gives Lower Bound's answer and stops on an equal value.
  2. Using high = arr.length - 1: the answer can be the insertion position at the very end, so use arr.length.
  3. Using high = mid - 1: a strictly greater value may be the answer, so retain it with high = mid.
  4. Assuming Upper Bound finds the target: it finds a boundary. Compare Lower and Upper Bound to test existence and count duplicates.
  5. Forgetting equality: equal values are not Upper Bound candidates; only strictly greater values qualify.

7. COMPLEXITY (The Math)

Time Complexity: O(log N)

Every iteration halves the remaining search area, so 1 million values take about 20 checks.

Space Complexity: O(1)

The loop uses only low, high, and mid.

8. REAL WORLD (Applications)

  • Counting occurrences: upper_bound(x) - lower_bound(x) counts x.
  • Range queries: upper_bound(2000) counts sorted prices less than or equal to 2000.
  • Bucket boundaries: find where a sorted grade or measurement band ends.
  • Database range scans: quickly find the cutoff row for price <= 2000.
  • Scheduling: find the first meeting strictly after a given time.

9. PATTERN RECOGNITION (Advanced) — Lower Bound vs Upper Bound

Both are one template: find the first position where a condition becomes true.

  • Lower Bound: first position where arr[i] >= target.
  • Upper Bound: first position where arr[i] > target.
  • Count equal to X: upper_bound(X) - lower_bound(X).
  • Count less than or equal to X: upper_bound(X).
  • Range [first,last]: first = lower_bound(X), last = upper_bound(X) - 1.
Key takeaway: Memorize one "find the first true" template and turn the comparison dial from >= to >.
