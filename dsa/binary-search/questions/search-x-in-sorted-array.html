Intro of Binary Search.

Big Picture (read this first, 30 seconds): Binary Search finds a number in a sorted list by checking the middle item, then throwing away half the list based on whether your target is bigger or smaller. It repeats this on the smaller half, again and again, until it finds the answer. This is why it is so fast: for 1 billion items, it needs only about 30 checks instead of a billion. Keep this one line in your head — everything below explains it in full detail, step by step.

RequirementSorted data
TimeO(log N)
Iterative spaceO(1)

1. WHY (Motive) — Linear Search vs Binary Search

Imagine you have 1 Billion sorted numbers in a list. You need to find one number in it.

Linear Search (the slow way)

  • It checks one item at a time — first item, then second, then third, and so on.
  • In the worst case, it checks all 1 billion items before finding the answer or realizing it is not there.
  • That is a LOT of work.

Binary Search (the fast way)

  • It cuts the search area in half every single time.
  • For 1 billion items, it only needs about 30 steps to find the answer.
  • Just 30 steps, instead of a billion.

Simple takeaway: Linear Search = check everything = slow (called O(N)). Binary Search = cut in half each time = fast (called O(log N)). For big data, this difference is huge. This is why we learn Binary Search.

2. CONDITION (Prerequisite) — The Data Must Be Sorted

Binary Search only works if the list is sorted, arranged in order, small to large or large to small.

Why? The whole trick is this: if we check the middle item and our answer is smaller, we can safely skip the entire right side because everything there is even bigger. This only works if the numbers are in order. If the list is not sorted, the middle item tells us nothing useful.

Rule to remember: No sorted data = No Binary Search. If your data is not sorted, sort it first, or use Linear Search instead.

3. INTUITION (The Core Logic) — The â€œGuess the Number” Game

You have probably played this game before: â€œI am thinking of a number between 1 and 100. Try to guess it in as few tries as possible. After every guess, I will only say higher or lower.” The smartest first guess is 50 — right in the middle.

  • Guess 50. If the friend says â€œhigher,” numbers 1“50 are gone forever.
  • Guess 75. If the friend says â€œlower,” the answer is between 51 and 74.
  • Guess the middle of what remains, and repeat.

Every guess cuts the remaining numbers in half. In just 7 guesses, you can find any number between 1 and 100.

This exact idea is Binary Search: â€œHigher” means the target is bigger than the middle, so search the right half. â€œLower” means the target is smaller, so search the left half. Repeat until you land on the answer. Throwing away half the possibilities every time is called Divide and Conquer.

4. DRY RUN (Simulation) — Watching the Pointers Move

We use three pointers: low (L) is the start of the current search area, high (H) is the end, and mid (M) is the middle point we check.

We are searching for the number 26.

arr[M] = 16. The target 26 is bigger, so throw away the left half, indexes 0“7. Move L to 8.

5. CODE (Implementation + Comments)

Here is the same logic written in three popular languages. Read the comments because they explain what each line does. The visualizer button opens the same algorithm with that language selected.

Open visualizer â†’ 
def binary_search(arr, target):
        low = 0                      # start of the search area
        high = len(arr) - 1          # end of the search area

        while low <= high:           # keep going while there is still something to check
          mid = low + (high - low) // 2   # find the middle point (safe way, avoids errors)

          if arr[mid] == target:   # middle value matches what we want
            return mid           # we found it — return its position
          elif arr[mid] < target:  # our number is bigger than the middle value
            low = mid + 1        # so skip the left half, search the right half
          else:                    # our number is smaller than the middle value
            high = mid - 1       # so skip the right half, search the left half

        return -1                    # loop ended without finding it — not in the list

6. MISTAKES & EDGE CASES (The Bugs)

  1. Writing mid = (low + high) / 2: If low and high are very large, adding them can cause an error called overflow. Use low + (high - low) / 2 instead.
  2. Forgetting to return -1: If the number is not in the list, return -1 to clearly say â€œnot found.”
  3. Using low < high: This might miss checking the last possible item. Always use low <= high.
  4. Wrong pointer update: Use low = mid + 1 and high = mid - 1 or the search area may never get smaller and the loop can run forever.
  5. Using Binary Search on unsorted data: Always check that the list is sorted before searching.

7. COMPLEXITY (The Math)

Time Complexity: O(log N)

Every step cuts the list in half: N â†’ N/2 â†’ N/4 â†’ N/8 â†’ ... â†’ 1. The number of steps needed to get from N down to 1 is called logâ‚‚(N). For 1 billion items, logâ‚‚(N) is only about 30. This is why the time barely grows even when the data grows massively.

Space Complexity: O(1)

The iterative version uses only three small variables: low, high, and mid. It does not matter whether the list has 10 items or 10 billion; it still uses these same variables. A recursive version uses O(log N) stack space because function calls are stored in memory.

8. REAL WORLD (Applications)

  • Git Bisect: When a bug appears after hundreds of commits, it finds the exact commit by checking only a handful of them.
  • Database Indexing: Databases use tree structures similar to Binary Search to find rows quickly in tables with millions of records.
  • Autocomplete & Spell Checkers: Search sorted word lists.
  • Photo/Video Editing: Jump to a specific point in a large history or timeline.
  • Rate Limiters & Logs: Find events in time-ordered logs.

9. PATTERN RECOGNITION (Advanced) — â€œBinary Search on the Answer”

Binary Search is not only for finding a number in a list. It can cut any search area in half when it has a special property called monotonicity: things keep getting better or worse in one direction, like a sorted list does.

Example: Find the smallest possible truck capacity needed to deliver all packages within 5 days. You are searching a range of possible answers, from the smallest to the largest capacity. For any capacity, ask: â€œIs this capacity enough to finish in 5 days?”

  • Yes â†’ try a smaller capacity by searching the left half.
  • No â†’ try a bigger capacity by searching the right half.

This is called Binary Search on the Answer. It appears in â€œminimize the maximum” and â€œmaximize the minimum” problems, finding square roots or ranked values, and splitting resources fairly.

Key takeaway: Whenever possible answers behave in an ordered, predictable way, think Binary Search — even when there is no actual sorted array.
